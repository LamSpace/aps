## Context

`AcceleratedProxy.proxy()` builds a proxy by running a `Group[]` chain through `matchMethods`, producing a `MethodMapping` (method index → interceptor index) that drives bytecode generation. The generated class is cached by `{targetClass, interfaces, mapping, constructorArgs}` — not by interceptor instances. This means any two configurations that yield the same `MethodMapping` share the same generated class and cache entry.

The annotation-driven API is a thin sugar layer over this pipeline: reflect over an `@Intercept` object, convert each `@Around` method into a `Group`, and delegate to `proxy()`. The generated bytecode, `dispatch()` hash switch, `INVOKESPECIAL` fast path, and `WeakCache` are all untouched.

## Goals / Non-Goals

**Goals:**

- Reduce boilerplate: replace `Group.of(m -> m.getName().startsWith("get"), interceptor)` with `@Around("get*")`.
- Reach steady-state latency equivalent to a hand-written lambda by binding `@Around` methods via a `LambdaMetafactory` call site (no per-call `Method.invoke`).
- Keep the existing proxy API, generators, cache, and hot path byte-identical.

**Non-Goals:**

- AspectJ-style pointcut expressions (parameter/return-type predicates, logical combinators).
- Multi-interface `intercept(Class<?>[], ...)`.
- Composing annotation-driven groups with hand-written `Group`s in a single call.
- Flexible `@Around` argument signatures and primitive-return boxing.
- Memoizing the reflection result across `intercept()` calls (bytecode generation is already cached).

## Decisions

1. **Thin sugar layer, not generator integration.** The adapter is a `LambdaMetafactory` call site, so annotation-driven interception already reaches hand-written-lambda parity. Inlining annotated bodies into generated bytecode would buy nothing and would couple the feature to the generator. *Alternative considered:* generate a bridge method in the proxy class — rejected as over-engineering with zero measurable gain.

2. **Fixed `@Around` signature `(Object, Method, Object[])`.** This matches the `Interceptor` SAM exactly, so the metafactory needs no argument dropping. *Alternative considered:* flexible argument omission (`(args)`, `()`), which requires per-method signature validation plus argument-dropping adaptation — rejected (YAGNI).

3. **`LambdaMetafactory` captured-argument form.** `implMethod` is the direct `unreflect(m)` handle; the interceptor instance is captured via the factory type, and `getTarget().invokeWithArguments(instance)` materializes the call site. The impl's subtype return is widened to `Object` automatically. *Alternative considered:* `bindTo(instance)` + `asType(...)` — rejected, because `asType` yields a non-direct handle the metafactory cannot crack (`LambdaConversionException`).

4. **Three match dimensions, AND-combined, OR within each.** `value`/`glob` (name glob), `regex` (name regex), `annotatedWith` (direct method annotation) combine with AND across dimensions and OR within. `value` is a shorthand for a single glob. Glob uses `*` → `.*`, `?` → `.`, everything else `Pattern.quote`d; regex uses whole-name `matches`, not `find`.

5. **Deterministic name-sorted `@Around` order.** The resolver sorts `@Around` methods by name (then parameter types) before building `Group[]`, mirroring the cross-JVM determinism guarantee already made by `matchMethods`. First-match-wins and the duplicate-match warning are inherited from the existing `Group` chain.

6. **Reference return types only.** Primitive and `void` returns are rejected rather than auto-boxed, keeping the metafactory adaptation-free.

7. **Access via `LookupManager.getLookup`.** The adapter reuses the existing `internal.LookupManager` (`privateLookupIn` with public-lookup fallback), so public `@Around` methods always work and non-public methods in open modules work; closed named modules surface an `IllegalArgumentException` pointing at `--add-opens` (consistent with the JPMS roadmap item).

## Risks / Trade-offs

- **Per-call reflection if implemented naively** → Mitigated by the `LambdaMetafactory` adapter; verified against a minimal prototype (String→Object widening and captured-argument binding both work).
- **Non-public `@Around` methods in closed named modules fail to bind** → Surfaced as a clear `IllegalArgumentException`; documented as a JPMS limitation consistent with the existing class-proxy path.
- **Creation-time reflection cost** → Runs only at `intercept()` call time, outside any measured loop; the expensive part (bytecode generation) is already cached by `WeakCache`.
- **`annotatedWith` checks only the directly-declared method annotations** → Deliberate simplification; meta-annotation / `@Inherited` traversal is out of scope.

## Migration Plan

None — purely additive. Existing `proxy()`, `Group`, `Interceptor`, and `MethodPredicate` behavior is unchanged.
