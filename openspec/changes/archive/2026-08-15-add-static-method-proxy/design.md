## Context

`MethodDispatcher.dispatchMethods` iterates `targetClass.getDeclaredMethods()` and skips `static`/`final`/`private` members, and the generated subclass's interceptor storage and `dispatch(Method, Object[])` are instance-bound (`this`-based fields). Static methods do not participate in virtual dispatch: `INVOKESTATIC` resolves to the declaring class at compile time, so a same-signature static method in the generated class is reachable only by reflecting on (or binding a `MethodHandle` to) that class. See proposal.md — Why.

## Goals / Non-Goals

**Goals:**

- A `proxyStatic` entry point returning a generated `Class<?>` whose static methods shadow the target's public static methods.
- Reuse the existing `Interceptor` contract with `proxy == null`; the original is invoked via `method.invoke(null, args)`.
- Zero change to the existing `proxy()` path and its generated bytecode.

**Non-Goals:**

- Transparently intercepting `Target.staticMethod()` call sites (requires target-class instrumentation, not subclass generation).
- Interface static methods, non-public static methods, and `final`/`private` static methods.
- Combining static and instance proxying in one class, or caching static proxy classes.
- Static proxying for the annotation-driven `intercept()` API; hot-load/hot-replace.

## Decisions

1. **`proxyStatic` returns `Class<?>`, not a wrapper or `MethodHandle`.** The caller already chooses reflection or `MethodHandle`; the performance ceiling is set by that entry mechanism, not by OpenProxy, so a bare `Class` is the minimal artifact and adds no indirection. Alternative (a `MethodHandle`-returning helper) was rejected as extra API surface for no measured gain.

2. **Generated class `extends Object`, defined in `io.github.lamspace`, no `LookupManager`.** The feature targets `public` static methods only, so no in-target-package access or JPMS `--add-opens` is needed. Because the class is unrelated to the target (no inheritance), "shadowing" is just declaring same-signature statics — there is no method-hiding verifier constraint. Alternative (extend the target) was rejected: it drags in constructor/abstract/final-class concerns for no benefit.

3. **Static proxies are uncached.** Interceptor state is class-global (static fields), so sharing a generated class across interceptor instances would race; the existing instance-agnostic `WeakCache` is the wrong tool. Per-call generation is a startup cost, and hidden classes stay GC-eligible once the caller drops the `Class`. Alternative (cache keyed on interceptor identity) was rejected for the weak-key/GC implications.

4. **Interceptor contract reused with `proxy == null`; original via `method.invoke(null, args)`.** No new interface, no static `dispatch` method. The reflection call is the interceptor's explicit opt-in and is JIT-backed. Alternative (a `StaticInterceptor` interface, or a generated static hashCode dispatch + `invokeStatic` helper) was rejected as more surface for a niche path.

5. **Passthrough shadows emitted for non-matching statics** (direct `INVOKESTATIC` to `method.getDeclaringClass()`), so the returned class always exposes the target's full static surface and never surprises callers with a missing method.

6. **`public` static methods only.** Non-public statics need `setAccessible`/opens for the interceptor's `method.invoke`, which overlaps the separate JPMS roadmap item; deferred rather than half-implemented.

7. **Method collection walks the hierarchy, subclass-first dedup.** Static methods aren't covered by `getDeclaredMethods()`-only iteration (no virtual dispatch), so inherited statics must be enumerated explicitly; dedup by `name + parameterTypes` with subclass declarations winning matches JVM hiding semantics. The result is stable-sorted by `name`, then `parameterTypes` — the same sort `matchMethods` applies — so `mapping.indices()[i]` aligns with the `i`-th shadow.

## Risks / Trade-offs

- **[Bytecode correctness] The static shadow's local-variable slots start at `0` (no `this`), unlike the instance path's `1`.** → Mitigation: dedicated `StaticMethodGenerator` rather than reusing `MethodDispatcher`; `BytecodeUtils` box/unbox helpers are shared; tests cover primitive/reference/void round-trips and overloads.
- **[Correctness] The `final`-static skip is a scope choice, not a JVM constraint** (an unrelated class *could* shadow a final static). → Mitigation: documented in the spec as "not shadowed"; lifting it later is a one-line change without breaking existing shadows.
- **[Access] The interceptor's `method.invoke(null, args)` requires the declaring class and method to be public.** → Mitigation: scoped to `public static` methods; non-public deferred to the JPMS item.
- **[Regression] Any accidental edit to the shared instance-path code could change `proxy()` behavior.** → Mitigation: the feature touches only new files plus additive `AcceleratedProxy` methods; the existing JMH suite is re-run as a guard.
