## Context

Interface proxying currently defines the generated hidden class with `MethodHandles.lookup()` in the `io.github.lamspace` package, so only `public` interfaces can be implemented. See `proposal.md` — Why for motivation.

Two JVM rules shape the design: (1) a package-private interface is accessible only from its own runtime package, and (2) a hidden class lives in exactly one package — the package of the lookup used to define it.

## Goals / Non-Goals

**Goals:**

- Proxy package-private interfaces without changing the all-public path's generated bytecode.
- Reject cross-package non-public interface arrays with a clear `IllegalArgumentException`.

**Non-Goals:**

- Private or `protected` nested interfaces (require nestmate access).
- Non-public interfaces in named modules whose package is not open to the unnamed module (needs `--add-opens`).
- Any change to the existing signature / return-type / `default` conflict rules.

## Decisions

1. **Anchor package = the single package shared by all non-public interfaces; all-public → `io.github.lamspace/`.** Discrimination by `Modifier.isPublic`.
   - *Alternative:* always place the class in the first interface's package. *Rejected:* it would make `privateLookupIn` fire for public JDK interfaces in strongly-encapsulated modules (`java.util.function.Function`), regressing the item-8 interface path.
2. **On-demand private lookup.** Use `LookupManager.getLookup(anchor)` only when a non-public interface exists; otherwise `MethodHandles.lookup()`. No change to `LookupManager` — its `privateLookupIn` + `--add-opens` fast-fail already has the right semantics.
3. **`InterfaceGenerator` gains a `packagePrefix` constructor parameter.** For the all-public case the prefix resolves to the same `io/github/lamspace/` literal, so the generated name is byte-identical; for the non-public case it is the anchor's package.
4. **Validation runs in `proxyInterfaces` before the cache**, so the cross-package error surfaces as an unwrapped `IllegalArgumentException`, consistent with the existing return-type/default conflicts thrown from `matchMethods`.
5. **Cache key unchanged.** The first interface remains the weak key; `CacheParams` already carries the full interface array, so the generated package is a pure function of existing key material.

## Risks / Trade-offs

- [Regression of public JDK interface proxying] → Mitigated by a dedicated regression test (`proxy(java.util.function.Function.class, …)` succeeds without `--add-opens`) and by byte-identity of the all-public path.
- [Misleading `--add-opens` message for private nested interfaces] → Out of scope; they fail via `privateLookupIn` rather than silently misbehaving.
- [Default-package (unnamed) interface edge case] → The prefix derivation returns `""` for it; untested and not a target.

## Migration Plan

None — purely additive. No configuration, dependency, or existing-API behavior change.
