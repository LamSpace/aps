## Purpose

Let proxy creators run code before and after a class proxy's superclass constructor — observing, rewriting, or vetoing construction — without wrapping every `proxy()` call in a manual factory.

## ADDED Requirements

### Requirement: Constructor interception interface

The system SHALL provide a `ConstructorInterceptor` interface with a `before` method (`Object[] before(Constructor<?> ctor, Object[] args) throws Throwable`) and an `after` method with a default no-op implementation (`default void after(Object proxy, Constructor<?> ctor, Object[] args)`).

#### Scenario: Interface shape

- **WHEN** a user implements `ConstructorInterceptor` providing only `before`
- **THEN** the interface compiles and `after` is inherited as a no-op

#### Scenario: Functional use of before

- **WHEN** a user passes a lambda `(ctor, args) -> args` where a `ConstructorInterceptor` is expected
- **THEN** the lambda binds to the single abstract `before` method

### Requirement: Constructor interception entry points

The system SHALL provide `proxy(Class<T>, Interceptor, ConstructorInterceptor)`, `proxy(Class<T>, ConstructorInterceptor, Group...)`, and `proxy(Class<T>, Object[], ConstructorInterceptor, Group...)` overloads that create a class proxy whose construction runs the interceptor hooks.

#### Scenario: Intercepted class proxy

- **WHEN** the user calls `proxy(Target.class, interceptor, ctorInterceptor)`
- **THEN** a proxy extending `Target` is returned whose superclass construction runs `ctorInterceptor.before` then the superclass constructor then `ctorInterceptor.after`

#### Scenario: Null constructor interceptor rejected

- **WHEN** the user calls `proxy(Target.class, (ConstructorInterceptor) null, groups...)`
- **THEN** the system throws `IllegalArgumentException`

### Requirement: Hook ordering around superclass constructor

The system SHALL run `before` before the superclass constructor body and `after` after it has completed, with the instance fully initialized before `after` runs.

#### Scenario: Ordering

- **WHEN** a target class records a side-effect inside its constructor and a `ConstructorInterceptor` records side-effects in `before` and `after`
- **THEN** the observed order is `before`, then superclass constructor, then `after`

#### Scenario: after receives the proxy instance

- **WHEN** `after` captures its `proxy` argument
- **THEN** that argument is the same object as the proxy returned by `proxy(...)`

### Requirement: Correct constructor and arguments

The system SHALL pass to `before` the `java.lang.reflect.Constructor` selected for the superclass (chosen from the initial argument types) and the initial constructor arguments.

#### Scenario: before receives constructor and args

- **WHEN** the user calls `proxy(Point.class, new Object[]{3, 4}, ctorInterceptor, groups...)` for a `Point(int, int)` constructor
- **THEN** `before` receives a `Constructor` whose parameter types are `{int, int}` and an args array `{3, 4}`

### Requirement: Argument rewriting

The system SHALL pass the array returned by `before` to the superclass constructor, replacing the initial argument values. The superclass constructor overload is fixed by the initial argument types.

#### Scenario: Rewritten values reach super

- **WHEN** `before` returns a different array than it received
- **THEN** the superclass constructor observes the rewritten values

#### Scenario: Rewriting across boxed and null values

- **WHEN** `before` rewrites arguments to different boxed primitive, `String`, and `null` values matching the constructor's declared parameter types
- **THEN** the superclass constructor receives each value with the correct type

### Requirement: Construction veto

The system SHALL abort construction when `before` throws. A `RuntimeException` or `Error` SHALL propagate to the caller unchanged; a checked exception SHALL surface as `UndeclaredThrowableException`.

#### Scenario: RuntimeException veto

- **WHEN** `before` throws an `IllegalStateException`
- **THEN** `proxy(...)` throws that same `IllegalStateException` and no instance is created

#### Scenario: Checked exception veto

- **WHEN** `before` throws a checked `Exception`
- **THEN** `proxy(...)` throws an `UndeclaredThrowableException` whose cause is that `Exception`

### Requirement: Class proxies only

Constructor interception SHALL be available for class proxies only; an interface target SHALL be rejected.

#### Scenario: Interface target rejected

- **WHEN** the user calls a constructor-interception `proxy(...)` overload with an interface target
- **THEN** the system throws `IllegalArgumentException`

### Requirement: Non-intercepted proxies unchanged

Creating a proxy without a `ConstructorInterceptor` SHALL produce the same behavior and generated bytecode as before the feature, so existing proxies incur no construction-time overhead.

#### Scenario: No interception equals previous behavior

- **WHEN** the user calls `proxy(Target.class, interceptor)` (no constructor interceptor)
- **THEN** construction behavior and method interception are identical to the behavior before the feature existed
