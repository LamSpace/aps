# APS Phase 3: Constructor Interception — Design Spec

**Date:** 2026-08-15 **Status:** Design approved **Phase:** 3 — Advanced Features

## 1. Motivation

The proxy API can intercept every non-final instance method, but has no hook at object *creation* time. Frameworks often need to observe or influence construction — register a newly-created instance, inject a back-reference, or validate/veto constructor arguments — which today requires an explicit factory wrapper around every `proxy()` call site. This feature adds a constructor interception hook analogous to CGLib's `Enhancer` constructor callback:
user code runs **before** and **after** the superclass constructor body.

**Success criteria**

1. A new `ConstructorInterceptor` interface with `before` (pre-`super()`, may rewrite args or veto) and `after` (post-`super()`, observational, default no-op) methods.
2. New `proxy()` overloads accept a `ConstructorInterceptor` for class proxies; interface proxies are unaffected (constructor interception is class-only).
3. `before` runs before the superclass constructor, `after` runs after it, and the hook receives the correct `java.lang.reflect.Constructor` and arguments.
4. `before` may rewrite constructor argument values; the rewritten values are what the superclass constructor receives.
5. `before` may veto by throwing; the exception propagates to the caller.
6. The non-intercepted constructor path's generated bytecode is **byte-for-byte unchanged** — adding this feature cannot regress existing proxies (the
   `proxy(target, interceptor)` path stays identical).
7. Proxy-class caching remains correct: the generated class is interceptor-instance-agnostic (the `ConstructorInterceptor` instance is a constructor argument, like `Interceptor`), and the cache key gains only a boolean "intercept constructors?" flag.
8. Unit tests, a JMH benchmark, an updated roadmap, and updated README docs.

## 2. Design

### 2.1 Public API

New interface in `io.github.lamspace`:

```java
package io.github.lamspace;

public interface ConstructorInterceptor {

    /**
     * Called before the superclass constructor runs. May rewrite the constructor
     * arguments by returning a (possibly new) array; throwing aborts construction.
     * {@code this} is not yet initialized, so no proxy instance is passed.
     *
     * @param ctor the superclass constructor that will run (selected from the
     *             initial argument types at generation time)
     * @param args the initial constructor arguments, boxed
     * @return the arguments to pass to the superclass constructor; must be
     *         non-null with the same length as {@code ctor.getParameterCount()}
     */
    Object[] before(Constructor<?> ctor, Object[] args) throws Throwable;

    /**
     * Called after the superclass constructor has run and the instance is fully
     * initialized. Observational only; the default is a no-op.
     */
    default void after(Object proxy, Constructor<?> ctor, Object[] args) {
    }
}
```

New overloads on `AcceleratedProxy` (class proxies only):

```java
public static <T> T proxy(Class<T> target,
                          Interceptor interceptor,
                          ConstructorInterceptor ctorInterceptor)

public static <T> T proxy(Class<T> target,
                          ConstructorInterceptor ctorInterceptor,
                          Group... groups)

public static <T> T proxy(Class<T> target,
                          Object[] constructorArgs,
                          ConstructorInterceptor ctorInterceptor,
                          Group... groups)
```

`ConstructorInterceptor` is unrelated to `Interceptor` and `Object[]`, so these do not create overload ambiguity with the existing entry points.

### 2.2 Generated-constructor bytecode

JVM constraint that shapes the design: **`this` is not available until
`super()` returns** — before that, instance fields of `this` cannot be read or written, and `this` cannot be passed as an argument. The `ConstructorInterceptor`
reference is therefore read from its local-variable slot (not stored in a field), and the `Constructor` object is read from a static field populated in `<clinit>`.

Generated constructor when interception is on (interception off keeps the current bytecode exactly):

```
<init>(Interceptor..., ConstructorInterceptor ctorInterceptor, [superArgs]):
  1.  box superArgs into Object[] args            (BytecodeUtils.boxPrimitive)
  2.  GETSTATIC _ctor$                            (the reflected Constructor)
  3.  ALOAD ctorInterceptor slot; ALOAD args
      INVOKEINTERFACE ConstructorInterceptor.before
      -> Object[] rewritten                       (store in a local slot)
  4.  ALOAD 0; for each super-ctor param: ALOAD rewritten, pushInt(i), AALOAD,
      CHECKCAST/unbox to the declared type; INVOKESPECIAL super.<init>(typed...)
  5.  ALOAD ctorInterceptor slot; ALOAD 0; GETSTATIC _ctor$; ALOAD rewritten
      INVOKEINTERFACE ConstructorInterceptor.after
  6.  this._interceptor$i = arg                    (unchanged from today)
  RETURN
```

- `_ctor$` is a `static final Constructor<?>` field populated once in `<clinit>`
  via `targetClass.getDeclaredConstructor(paramTypes)` — the same one-time reflection pattern already used for method `Method` objects in `generateClinit`.
- Boxing/unboxing reuse `BytecodeUtils.boxPrimitive` / `unboxPrimitive` /
  `loadOpcode` (the same helpers `InterfaceDispatcher` uses).
- The superclass constructor is selected at **generation time** from the initial
  `constructorArgs` types (`findConstructor`). `before` may rewrite *values* but not the overload — the declared parameter types are fixed by the selected constructor, and a value of an incompatible type fails the `CHECKCAST`.

### 2.3 Cache key

`CacheParams` gains `boolean ctorIntercept`, folded into `equals`/`hashCode`. The generated class depends only on *whether* interception is present, not on the
`ConstructorInterceptor` instance (which, like `Interceptor` instances, is passed through the generated constructor). Default `false` keeps every existing cache entry and proxy class untouched.

### 2.4 Instantiation path

`proxy(Class, Object[], ConstructorInterceptor, Group...)` mirrors the existing
`proxy(Class, Object[], Group...)` instantiation logic, with the generated constructor parameter list extended by one `ConstructorInterceptor.class` slot (immediately before the superclass args). The no-arg convenience overloads delegate with `new Object[0]`.

## 3. Error handling

1. `target == null`, `groups` null/empty, `constructorArgs == null` → same
   `IllegalArgumentException` as the existing `proxy(Class, Object[], Group...)`.
2. `ctorInterceptor == null` → `IllegalArgumentException` (explicitly required on the interception overloads).
3. `before` throws a `RuntimeException` or `Error` → construction aborts; the exception propagates to the caller with full fidelity.
4. `before` throws a checked exception → wrapped by the generated constructor in
   `UndeclaredThrowableException` (consistent with `Interceptor.intercept`'s checked-exception handling), then surfaced to the caller.
5. `before` returns `null` or an array of the wrong length → fails fast with a
   `NullPointerException` / `ArrayIndexOutOfBoundsException` from the generated constructor; documented as a contract violation, not an explicit guard.
6. The non-interception path keeps its existing `RuntimeException("Failed to
   create proxy ...")` wrapping; only the interception path unwraps
   `InvocationTargetException` to surface the veto cause.

## 4. Testing

New `src/test/java/io/github/lamspace/ConstructorInterceptionTest.java`
(integration), plus a light
`src/test/java/io/github/lamspace/generator/ClassGeneratorTest.java` for the
`_ctor$` `<clinit>` emission if the generator path warrants it.

| #  | Scenario                               | Coverage                                                                                                            |
|----|----------------------------------------|---------------------------------------------------------------------------------------------------------------------|
| 1  | Ordering                               | `before` → superclass ctor body → `after`, via a recording side-effect                                              |
| 2  | Correct `Constructor` and initial args | overloaded ctors: `ctor.getParameterTypes()` matches the chosen one; `args` holds initial values                    |
| 3  | Argument rewrite                       | `before` returns a new array; superclass field receives the rewritten values                                        |
| 4  | Rewrite across primitive/boxed/null    | int/long/double/boolean/String/null all survive box→rewrite→unbox                                                   |
| 5  | Veto (RuntimeException)                | `before` throws; exception propagates; no instance created                                                          |
| 6  | Veto (checked exception)               | `before` throws checked; surfaces as `UndeclaredThrowableException`                                                 |
| 7  | `after` receives `this`                | `after`'s `proxy` param `==` returned instance; can read fields/methods                                             |
| 8  | Default `after`                        | implementing only `before` does not NPE                                                                             |
| 9  | No-arg constructor                     | `before` receives empty array; can return empty; super no-arg                                                       |
| 10 | Cache correctness                      | same target+groups + different `ConstructorInterceptor` instances share the generated class but run their own hooks |
| 11 | Cache isolation                        | `proxy(target, interceptor)` and `proxy(target, ctorInterceptor, ...)` use distinct cache keys                      |
| 12 | Non-intercepted path unchanged         | `proxy(target, interceptor)` behaves exactly as before (regression)                                                 |
| 13 | Negative: null `ctorInterceptor`       | throws `IllegalArgumentException`                                                                                   |
| 14 | Convenience overload                   | `proxy(target, interceptor, ctorInterceptor)` == `proxy(target, ctorInterceptor, Group.otherwise(interceptor))`     |

## 5. Benchmark

**Conclusion: zero impact on the non-intercepted path, and interception cost is paid once per instance, not per method call.** The non-intercepted constructor bytecode is unchanged, so `proxy(target, interceptor)` and method-call latency cannot regress; the guard is procedural (run the existing JMH suite before/after and require identical class- and interface-proxy numbers).

Add `src/test/java/io/github/lamspace/benchmark/ConstructorInterceptionBenchmark.java`
measuring instances created per second and ns-per-instance for:

1. direct `new Target(...)` (baseline),
2. `proxy(target, interceptor)` (existing, no interception),
3. `proxy(target, ctorInterceptor, ...)` with `before` + `after` both present,
4. CGLib `Enhancer` constructor callback (already a test dependency) as a relative reference.

Report the per-instance overhead and ratio vs. baseline in
`docs/benchmark-results.md` (and `_cn`). Interpret the result as construction-time cost (boxing + one `before` + one `after` interface call per instance), not a steady-state per-call cost.

## 7. Deliberate decisions

1. **Class proxies only.** Interface proxies have no superclass constructor to intercept (only `Object.<init>()`), so `before` would have nothing to rewrite. Added later if a symmetrical `after`-only hook is ever wanted.
2. **`ConstructorInterceptor` instance passed via constructor, not baked in.**
   This keeps the generated class instance-agnostic and preserves cache sharing, matching how `Interceptor` instances already work.
3. **Cache key is a boolean, not the instance.** Only *presence* changes the generated bytecode; the instance is a runtime argument.
4. **Constructor overload fixed at generation time.** `before` rewrites values, not the overload; this keeps the generated bytecode simple (no per-call reflective overload search) and is the documented contract.
5. **`after` receives the rewritten args.** It observes the actual values passed to the superclass constructor, not the originals.
6. **`this`-before-`super()` handled via local slots + a static `Constructor`
   field**, not by storing the interceptor in an instance field early (which the JVM verifier forbids).
7. **No explicit null/length guard in generated bytecode.** A contract violation fails fast with a natural NPE/`ArrayIndexOutOfBoundsException`; adding guard bytecode to every generated constructor would tax the hot path for a case the contract already excludes.

## 8. Out of scope

- Interface-proxy constructor interception.
- Replacing the created instance (factory-style control) or constructing a *different* subclass at runtime.
- Changing which superclass constructor overload runs from inside `before`.
- Constructor interception for the annotation-driven `intercept()` API.
- Hot-load/hot-replace of constructor interception (separate roadmap item).
